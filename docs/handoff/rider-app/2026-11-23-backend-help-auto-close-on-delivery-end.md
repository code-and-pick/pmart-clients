# 배송이 끝나면 열린 도움요청 자동 완료

보낸 앱: rider-app (PC 5)
받는 백엔드 영역: delivery (delivery-execution — 도움요청, case 연동)

- 작성: 2026-11-23
- 사용자(2026-11-23): "배송 중에 연락 온 건 배송 끝나면 처리 필요 없게 완료시키던가, 아니면 배송 끝난 건 주문 내역도 라이더도 나중에 확인할 수 있게 볼 수 있게" → 둘 다 하기로 정했다(앱은 끝난 배송 읽기 전용 화면을 만든다 — 아래 3).

## 지금 문제
- 배송이 끝나도(전달 완료·반납 완료·취소·전달 실패 확정) 도움요청은 OPEN·IN_PROGRESS 로 남는다.
- 그래서 상담원이 그 뒤에 대화를 보내면 라이더 알림함에 "지원센터 답장이 왔어요"가 뜬다. 라이더 입장에서는 배송이 이미 끝나 할 수 있는 게 없다.

## 바라는 것
1. **배송이 끝 상태가 되면**(COMPLETED · RETURNED_TO_STORE · CANCELLED · FAILED 등 더 진행하지 않는 상태) 그 배송의 OPEN·IN_PROGRESS 도움요청을 서버가 RESOLVED 로 닫아 주세요.
   - 닫은 쪽은 사람이 아님을 알 수 있게 해 주세요(예: `resolvedBy` = "system:delivery-ended", `resolutionNote` = "배송이 끝나 자동 완료"). 화면은 이 값을 그대로 보인다.
   - 연결된 case 사건은 어떻게 할지(같이 닫기 / 사건은 열어 두기) 정해서 알려 주세요. 앱 쪽 바람은 사건이 열려 있어도 도움요청은 닫히는 것이다.
2. 닫힌 뒤 직원이 그 도움요청에 대화를 보내면 지금처럼 409 `HELP_REQUEST_CLOSED` 가 나면 된다. 라이더에게 더 할 말이 있으면 라이더 문의(case `POST /inquiries` 직원 쪽 또는 공지)로 하게 된다.
   - 백오피스는 닫힌 도움요청의 입력 칸을 이미 숨긴다.
3. 앱은 끝난 배송을 배달기록에서 열어 주문 요약·도움요청 대화를 읽기 전용으로 보인다. 지금 계약으로 된다(`GET /deliveries/{id}` 배정 라이더 본인, `GET …/help-requests`, `GET …/help-requests/{id}/messages`).
   - 끝난 뒤에도 이 조회들이 404 가 나지 않는지 확인 부탁드린다(배정이 풀린 배송 등).
