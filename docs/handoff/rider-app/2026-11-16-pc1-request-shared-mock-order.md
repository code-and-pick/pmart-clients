# 요청: 고객앱·라이더앱 목 데이터를 같은 주문·같은 지점으로 맞추기

- 보낸 앱: rider-app(PC 5)
- 받는 쪽: **PC 1(customer-app)** — 백엔드 아님. 이 문서는 PR 설명에도 적는다.
- 작성: 2026-11-16
- 계기: 사용자 질문 "배달앱에서 사용하는 주문 번호나 MFC 위치가 고객앱에도 똑같이 적용되어 있니?" → 아니라고 답하자 사용자가 "1번 2번 다 진행해"(1 = 목 데이터 맞추기, 2 = 화면용 주문번호 백엔드 요청 `docs/handoff/all/2026-11-16-backend-display-order-number.md`).
- 상태: 라이더앱 쪽은 맞춤(미커밋). **고객앱 쪽은 PC 1 이 고쳐야 한다** — PC 5 는 고객앱 코드를 고치지 않는다.

## 왜
목 모드는 공용 서버가 없어 두 앱이 따로 돈다. 그래도 시연할 때 "고객이 낸 주문 = 라이더가 배달하는 주문"으로 보이도록 **진행 중 주문 1건과 지점 1곳**을 같은 값으로 맞춘다. 실서버에서는 서버 값이 같으므로 이 맞추기는 목 전용이다.

## 기준 주문(두 앱 공통)
| 항목 | 값 | 라이더앱(반영됨) | 고객앱 지금 → 바꿀 값 |
|---|---|---|---|
| 주문 ID | `48213075`(8자리) | 배송 `dlv-1` 의 `orderId`·주문정보 주문번호 | `order-seed-4` → `48213075` |
| 배송 ID | `dlv-1` | 그대로 | shipment `dlv-s5` → `dlv-1` |
| 지점(MFC) | `MFC-BSJ-01` **PMart 부산진구지점**, 부산시 부산진구 동천로 109, 삼한골드게이트 2층 | 배차·배송·기록 목 | `MFC-MOCK-01` → `MFC-BSJ-01`(장바구니·배송지 판정·주문 모두) |
| 배송지 | 부산 부산진구 전포대로 210, 전포 한빛아파트 103동 1203호, 받는 분 김피마 | 전달지(`drop-info` 목) | 서울 송파구 올림픽로 300 101동 1001호 → 왼쪽 값(받는 분 김피마 그대로) |

| 품목 | 그릭요거트 플레인 400g × 3 = 17,940원 | 주문정보 품목·메뉴금액 | 그대로 |
| 배달 요청사항 | 문 앞에 두고 벨은 누르지 말아 주세요 | 배달 요청사항 | 그대로 |

- 다른 목 주문(`order-seed-1`~`3`)도 화면에 8자리로 보이게 하려면 겹치지 않는 번호(예: `21045318`·`21045326`·`21045334`)로 바꾸면 된다. 라이더앱의 다른 목 배송(묶음·배달리스트)은 고객앱 주문과 짝이 없다(라이더 시연용).
- 두 번째 배송지 판정 목(`MFC-MOCK-02`)은 부산 다른 지점(예: `MFC-BHU-01` 부산해운대지점)으로 바꾸면 자연스럽다.
- 지점 26곳(이름·주소·어림 좌표)은 라이더앱 `apps/rider_app/lib/shared/mfc_directory.dart` 에 있다. 앱끼리 import 하지 않으므로, 같은 목록이 고객앱에도 필요하면 `packages/`(PC 1 소유)로 옮기는 것을 PC 1 이 정한다.
