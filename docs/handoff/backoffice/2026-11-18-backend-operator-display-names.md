# 운영자 ID(OP-…) → "이름 · 사번" 표시용 조회 요청 (기본 백오피스·인사팀 백오피스)

보낸 앱: backoffice (인사팀 백오피스 포함 — PC 2)
받는 백엔드 영역: platform (hr-service — PC 1)
날짜: 2026-11-18

## 왜
화면 번호 규칙(ADR-0070) 확대 요청을 받았다. 백엔드 딜리버리 세션(PC 5)이 사용자 지시("번호 규칙 통합백오피스랑 인사백오피스에도 적용했어? 안됐으면 요청해")로 보냈다. 요청 내용은 "운영자 ID(OP-…)가 목록·처리자 칸에 보이면 '이름 · 사번'으로 바꿔 달라"이다.

지금 OP-… 가 그대로 보이는 곳:
- **기본 백오피스**
  - 승인함·승인 상세: 요청자, 결정 이력의 결정자
  - 처리 대기: 최근 재시도한 사람
  - 접수 건: 맡은 사람, 이력의 행위자, 메모 작성자
  - 개인정보 열람 기록: 연 직원
  - 교대 인계: 전임·후임
- **인사팀 백오피스**: 처리자 칸. 권한 상세의 승인자·회수자는 이미 이름으로 보임 — employee-auth 가 붙여 줌, 2026-11-17

직원 토큰으로 부를 수 있는 일괄 조회가 없다.
- `GET /internal/employee-names`: 서비스 토큰 전용이고, 이름만 준다(사번 없음).
- `GET /hr/employees/{operatorId}`: 한 명씩이고 인사 정보 전체라 HR_ADMIN 용이다.

## 요청
- **R1. 운영자 ID 여러 개 → 표시 정보를 직원 토큰으로 한 번에 받는 조회.**
  - 예: `GET /hr/employee-labels?operatorIds=OP-a&operatorIds=OP-b`(50개까지).
  - 줄 = `{ operatorId, name, employeeNumber }`. 퇴사자도 포함한다(지난 기록 표시용). 모르는 ID 는 빠진다.
  - 이름·사번 외의 인사 정보(메일·소속·연락처)는 싣지 않는다.
  - 누가 부를 수 있는지(모든 OPERATOR 인지, 역할 제한인지)와 이름을 가릴지(예: 홍*동)는 백엔드·사용자가 정해 주세요.
- **R2. (선택) bff 화면 응답에 같은 표시를 실어 주기.**
  - 대상: 승인함, 처리 대기, 접수 건함의 처리자·요청자 칸.
  - 이렇게 되면 화면이 따로 부르지 않아도 된다.

## 받으면 화면은
목록·처리자 칸에 "홍길동 · P2026-00014" 를 보이고, OP-… 는 상세의 접힌 "시스템 번호" 칸에만 둔다(ADR-0070 과 같게). 이름을 못 읽으면 "확인 불가"로 보이고(없음과 구분), 받기 전까지는 지금처럼 OP-… 를 그대로 둔다.
