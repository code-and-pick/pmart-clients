# 요청 — 대시보드 "곧 품절" 상품 수(하루 판매량 기준)

보낸 앱: backoffice (PC 2 — 통합 백오피스 대시보드 매출 탭 "센터별 품절 SKU" 칸)
받는 백엔드 영역: mfc (mfc-inventory `GET /stock-summaries`·`/stock-stream`, 하루 판매량 d 는 mfc-inbound 발주 수량 추천과 같은 값). 담당이 다르면 알려 주세요.
작성: 2026-11-25

## 왜
- 사용자(PC 2, 2026-11-25): "근데 품절되기 전에 알아야 하는 거 아님?" — 지금 칸은 이미 품절된 상품(가용 A = E − R ≤ 0)만 센다(IV-5, mfc-inventory 0.28.0).
- 2026-11-18 에는 안전재고(Q-13)가 정해지지 않아 "재고 부족" 대신 "품절"로만 정했다. 그 뒤 mfc-inbound 0.21.0 발주 수량 추천(MI-4)이 센터 공급 정책 표의 안전재고 SS = d × safetyDays(시작값 1일치)를 쓰기 시작했다.
- **사용자 결정(2026-11-25)**: 곧 품절 = **하루 판매량 기준**(고른 안: "발주 수량 추천과 같은 기준 — 지난 28일 하루 평균 판매량만큼 이하로 남은 상품"). 고정 개수(가용 N개 이하) 안은 고르지 않음.
- 화면이 기준을 지어내지 않는다 — 판매량·정책은 서버 값이라 서버 집계를 요청한다.

## 요청

### LS-1 `GET /stock-summaries` 에 곧 품절 수
- 줄마다(센터) `lowStockSkuCount` — 그 센터 **취급 ON 상품** 중 **0 < A ≤ SS** 인 상품 수(품절과 겹치지 않게 A > 0 만).
  - SS = d × safetyDays — mfc-inbound 발주 수량 추천과 **같은 d·같은 공급 정책 표**(센터·온도대, 없으면 전 센터 기본). 지금 시작값이면 "하루 판매량 이하로 남음".
  - d(이동평균)를 못 정하는 상품(이력 부족·정책 없음)은 세지 않고 따로 `lowStockUnknownSkuCount`(0·무제한으로 채우지 않기 — 발주 추천의 `reason` 과 같은 뜻).
- 기준을 화면에 한 줄로 보이게 응답에 `lowStockBasis`(예: `{ safetyDays: 1, historyDays: 28 }` — 센터·온도대마다 다르면 "센터 정책"이라고만 적을 수 있게 알려 주세요).
- 권한·센터 범위는 지금 stock-summaries 와 같다(본사 관리자 모든 센터, 센터 계정 자기 센터).

### LS-2 곧 품절 상품 목록(숫자를 누르면)
- 예: `GET /stock-summaries/{mfcId}/low-stock-skus?cursor=&size=` — `{ sku, productId, availableQty, dailyQty(d), safetyQty(SS) }`, 남은 일수 적은 순. 품절 목록도 같은 모양으로 있으면 같이(지금 품절 수만 있고 목록은 없다).

### LS-3 실시간(선택)
- `/stock-stream` 의 `summary-changed` 를 곧 품절 경계(A 가 SS 를 넘나들 때)에도 보내 주면 화면은 지금처럼 2초 모아 다시 읽는다(화면은 세지 않음). d·SS 가 하루 한 번 바뀌는 것은 다음 읽기에 반영돼도 된다.

## 화면(받은 뒤)
- 대시보드 매출 탭 품절 칸: "품절 N개 · 곧 품절 M개", 센터별 줄에도 둘 다. 곧 품절은 주의(주황) 점, 숫자를 누르면 LS-2 목록. 기준은 칸 아래 한 줄("하루 판매량 이하로 남음 · 지난 28일 평균").
- 모르는 상품 수(`lowStockUnknownSkuCount`)가 있으면 "판매 이력이 부족해 못 셈 K개" 회색 한 줄 — 0 으로 보이지 않게.
