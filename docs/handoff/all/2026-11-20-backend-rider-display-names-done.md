# 회신 — MFC 화면 라이더 표기 반영(RS-MFC)

보낸 앱: mfc-app·mfc-backoffice (PC 3)
받는 백엔드 영역: mfc (delivery 참고 — rider-service 0.18.0)
원 문서: `../pmart-backend/docs/handoff/clients/all/2026-11-20-request-rider-display-names-mfc.md`
날짜: 2026-11-20

## mfc-app (PDA)
- 인계 확인 목록·포장 인계 상태: "허가받은 라이더: 김*수 · 482913". **"포장대에 없음" 확인 창**도 같은 표기(전에는 라이더 ID 그대로 — 이번에 고침).
- 반납 인증번호: "라이더: 김*수 · 482913". 화면의 라이더를 모아 **한 번**에 묻는다(전에는 카드마다 한 번 — 이번에 고침).
- `GET /riders/display-names` 는 50개씩 나눠 묻고 합친다(전에는 51번째부터 버려 "라이더"로만 보였음 — 이번에 고침).
- 탈퇴(이름 null)는 번호만, 응답에 없는 ID 는 "라이더", 조회 실패는 "라이더(이름 못 읽음)". 라이더 ID 는 화면에 내지 않는다. 목 `rider-mock-1~3`·`r-7`·`r-9`.
- arb 자리 이름 `{riderId}` → `{rider}`(값은 표기 문자열).

## mfc-backoffice (웹)
- 요청의 6개 화면(센터 배송 목록·배차 지연·포장 인계 현황·회수품 받기(반납 인증번호)·센터 운영판·인계 확인) + 작업 상세·반입 대기는 `RiderLabel` 이 같은 틱의 라이더를 모아 50개씩 한 번 묻는다(main `b15b9e98`, 2026-11-20 이미 반영). 이번에는 낡은 주석·안 쓰는 "라이더 정보 비공개" 문구만 정리.
- 실패 표기는 요청의 "숨김" 대신 "라이더(이름 못 읽음)" — 클라이언트 규칙(조회 실패를 정상·없음처럼 보이지 않는다). 목록은 그대로 보인다.

## 시험
- PDA: `flutter analyze` 문제 없음, `flutter test` 237개 통과(새 — 확인 창 표기·조회 1번, 반납 화면 조회 1번, 50개씩 나눔).
