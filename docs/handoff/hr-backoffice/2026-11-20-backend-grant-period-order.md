# 권한·근무 기간 순서 검사 요청 (인사 백오피스)

보낸 앱: hr-backoffice (PC 2)
받는 백엔드 영역: platform (hr-service)
항목: BR 번호는 PC 1 이 합칠 때 매겨 주세요.

## 무엇이 있었나

- 2026-11-20 사용자가 인사 백오피스(목 모드)에서 직원 OP-picker-1 에게 권한을 요청했다. 기간을 **2027-03-01 ~ 2026-11-20** 으로 넣었는데(종료일이 시작일보다 앞) 그대로 자동 승인돼 "승인된 권한"에 떴다.
- 계약 `hr-service.yaml` 의 `RequestedGrant.validFrom·validTo` 에는 순서 규칙이 없다. 400 검사 순서(0.6.0, HR-2)에도 기간 순서가 없다. 직원 등록의 `startDate·endDate`(근무 기간)도 같다.
- 그래서 화면 말고 다른 경로(API 직접 호출·다른 앱)로는 거꾸로 된 기간이 저장될 수 있다.

## 화면에서 한 것(2026-11-20)

- 권한 추가·변경 요청, 직원 등록의 권한 줄과 근무 기간은 종료일이 시작일보다 앞이면 안내하고 보내지 않는다.
- 판정은 두 날짜를 모두 넣었을 때만 한다. 비우면 서버가 근무 기간으로 채우기 때문이다.
- 목은 계약대로 두었다. 계약에 없는 거절을 지어내지 않았다.

## 요청

### GP-1 기간 순서 400

- `POST /hr/employees/{operatorId}/grant-requests`·`POST /hr/employees`(등록 권한 줄): `validTo < validFrom` 이면 400 `VALIDATION_FAILED`, `details[].field = grants[i].validTo`.
- 비워서 서버가 채운 값(근무 시작일·계약 종료일)으로 판정해도 거꾸로면 같은 400 이면 좋겠다. 예: validFrom 만 계약 종료일 뒤.
- 직원 등록·근무 기간 변경: `endDate < startDate` 이면 400, `field = endDate`.

### GP-2 이미 저장된 거꾸로 된 기간

- 목에서는 생겼지만 LAN 실서버에도 있는지는 모른다. 있으면 어떻게 다룰지(회수·바로잡기) 알려 주면 화면 안내를 맞추겠다.

## 회신 뒤 화면

- `details[].field` 로 해당 칸에 서버 문구를 보인다. 화면 검사는 그대로 둔다(보내기 전 안내).
