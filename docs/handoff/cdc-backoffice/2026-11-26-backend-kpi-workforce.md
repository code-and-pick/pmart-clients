## 1. 리포트·KPI — 운영 확인 지표

WMS 원문은 "별도 BI 대시보드나 성과 목표 수치를 추가하지 않는다"고 하고, 대신 **운영자가 원천 사건을 점검하는 확인 항목**을 정의한다(승인 수요 충족률·원수요 충족률·정상 수령률·사용 준비 시간·약속 준수·예외 운영량). 화면은 이 정의를 그대로 보이기만 한다 — 계산은 서버.

### KP-1 `GET /cdcs/{cdcId}/operating-metrics?from=&to=&mfcId=`(자기 센터 운영자) — 새 경로(이름은 백엔드 판단)
- 줄 = 확인 항목 하나: `metric`(위 6개 코드)·분자·분모·단위·값(분모 0 이면 N/A — 0·100% 로 바꾸지 않음)·`provisional`(미완료·미판정이 섞이면 잠정)·정의 버전·기준 시각.
- 원천 추적: 값마다 원천 행(TRF·출발·수령 ID) 목록이나 그 목록을 다시 조회할 거르기 값(BO-28 "지표가 원천 행까지 추적").
- 서로 다른 SKU·단위를 임의로 합한 비율은 내지 않는다(원문 규칙) — 단위가 섞이면 그 항목은 SKU 별로 나누거나 N/A.
- 쓰는 곳: 리포트·KPI 메뉴(기간·MFC 거르기, 항목별 값·잠정 표시·원천 보기), 대시보드 카드(선택).

### KP-2 `GET /cdcs/{cdcId}/outbound-summary/daily?from=&to=` — 일별 출고 추이(지금 outbound-summary 를 날짜 범위로)
- 줄 = 날짜 하나: 지금 `outbound-summary`(그날 TRF 상태별 수·승인·할당·피킹·부족·출발 수량) 모양 그대로. 최대 31일.
- 쓰는 곳: 리포트 메뉴 "일별 출고량" 표·막대.

## 2. 작업자·인력

cdc-outbound 0.23.0 `GET /cdcs/{cdcId}/workers` 로 **지금 위치·지금 작업**은 이미 보인다(평면도·대시보드에 붙임). cdc-outbound 설명에 "CDC 는 작업자·근무 정본이 아직 없어 근무·업무 자격·온도대 출입 검사는 뒤로"라고 되어 있다.

### WF-1 작업자별 처리량 — `GET /cdcs/{cdcId}/worker-throughput?date=&from=&to=`(자기 센터 운영자)
- 줄 = 작업자 하나: 운영자 ID·완료 작업 수·피킹 줄 수·피킹 수량(SKU 판매단위 그대로 — 단위 섞어 합치지 않음)·부족 보고 수·첫/마지막 실적 시각·주 구역(층·구역).
- 피킹 실적(cdc-outbound Task 결과)에서 나오는 값이라 새 정본은 필요 없을 것 같다(판단은 백엔드). WMS-dc-wave "작업자별 처리량·카트 적재량을 넘으면 작업 분할"과 같은 처리량.
- 쓰는 곳: 작업자·인력 메뉴(오늘 작업자별 표), 리포트 "작업자 생산성".

### WF-2 (설계·사용자 결정 필요) CDC 근무 — 근무조·출근·배치
- 원문(WMS 1179·1203)은 "작업자는 자기 센터·온도구역·업무/장비 권한·현재 근무·배정 상태를 확인"이라고만 하고 근무조 규칙·수치는 없다(plan §2 "3단계 — 새 설계").
- 필요한 것: 오늘 근무 중 작업자 목록(근무조·온도구역·업무 자격), 근무 시작·끝. 정본을 hr 에 둘지 cdc 쪽에 둘지, 근무조를 어떻게 정할지는 사용자 결정 — 정해지면 계약을 알려 주세요.
