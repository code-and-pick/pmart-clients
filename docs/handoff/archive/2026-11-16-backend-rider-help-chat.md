## 0. 지금 계약(백엔드 main 4bd6ce7a 기준)
- case-service 0.11.2, delivery-execution-service 0.5.1 어디에도 대화(메시지) API 가 없다.
- 접수 건 메모(`POST/GET /cases/{caseId}/notes`, 0.10.0)는 **본사 직원끼리만** 보는 기록이라 라이더 답장으로 쓸 수 없다. 도움요청 `resolutionNote` 도 직원에게만. → 라이더에게 보이는 대화는 **메모와 따로** 있어야 한다(라이더앱 요청과 같음).
- 백오피스에 이미 있는 것: 지원센터 › 접수 건(`kind=RIDER_HELP`) 집기·처리 끝내기·다시 처리하기, 상세의 "라이더 도움요청 내용"(execution 단건 — 유형·단계·처음 내용·사진 번호·상태·시각), 배송·주문·라이더 번호(refs).

## 1. 상담원 쪽에 필요한 API
1. **대화 읽기**(직원용): 한 접수 건(또는 도움요청)의 메시지를 오래된 순서로. 필드 — `messageId`, `sender`(RIDER / AGENT), `text`(500자 이하), `createdAt`, 직원에게만 `agentId`. 라이더가 처음 쓴 `detail`·`evidenceRefs` 를 첫 메시지로 넣을지, 도움요청 단건에서 따로 읽을지 정해 주세요(백오피스는 어느 쪽이든 맞춤).
   - 화면이 열려 있는 동안 새 메시지를 확인할 방법: 몇 초 간격 다시 읽기면 되는지, `after=<messageId|시각>` 같은 이어 읽기가 있는지.
2. **답장 보내기**(직원용): `Idempotency-Key`·`X-Source-System` — 같은 직원·같은 키 = 같은 메시지(재전송 때 두 번 보이지 않게). 결과 불명이면 대화 읽기로 확인.
   - 역할: 지금 RIDER_HELP 접수 건을 집고 닫는 역할(RIDER_OPS·OPERATOR_ADMIN)과 같게 할지, CS_AGENT 도 쓸 수 있는지.
   - 처리 끝난 건에 답장: 거절(409 등)이면 코드 이름을 알려 주세요. 화면은 "다시 처리하기 뒤 답장" 안내를 띄운다.
3. **목록의 새 메시지 표시**: 사건함 목록(`GET /cases?kind=RIDER_HELP` 또는 bff case-inbox)에 **서버가 정한 값**이 필요하다 — 예 `lastRiderMessageAt` 과 상담원 마지막 확인 시각, 또는 `unreadCount`/`hasUnread`. 화면이 메시지를 전부 읽어 계산하지 않는다. "읽음"을 남기는 방법(대화를 읽으면 자동인지, 따로 표시 명령인지)도.

## 2. 상태 — 라이더앱 표와 다른 점(맞춰 주세요)
- 백엔드 알림 `backoffice/2026-11-16-notice-help-request-case-link.md`(#55)대로면 **접수 건이 열리는 순간** 도움요청이 `IN_PROGRESS` 가 된다. 라이더앱 요청서의 "상담원이 사건을 집음 → 처리 중"과 다르다. 라이더 앱의 "접수됨(OPEN)"은 접수 건이 열리기 전 잠깐뿐. 이게 의도대로인지, 라이더에게 "상담원이 맡음"을 따로 보여야 하는지(예 사건 담당자 유무) 정해 주세요.
- **다시 처리하기**: 닫은 접수 건을 다시 처리하면 도움요청이 `IN_PROGRESS` 로 돌아온다. 그때 **라이더가 다시 쓸 수 있는지**(대화가 다시 열리는지) 정해 주세요. 라이더앱 요청서는 "닫힌 뒤 라이더는 못 쓰고 새 요청 안내"만 적었다.
- 넘기기(`transfers`)로 다른 팀이 맡으면 그 팀이 답장할 수 있는지.

## 3. 개인정보
- 대화에 고객 전화번호·출입 비밀번호가 들어갈 수 있다(라이더앱 요청서). 로그·이벤트에 남기지 않는 것은 메모와 같게.
- 실수로 쓴 개인정보를 **관리자가 가릴 수 있어야 하는지**(메모의 `…/maskings` 처럼 — 가리면 text null·가린 사람·사유) 정해 주세요. 라이더에게도 가려져 보이는지.
- 보관 기간·누가 읽을 수 있는지(센터 관리자 MFC_SUPERVISOR 는 지금 RIDER_HELP 를 보지 않음).

## 4. 받으면 백오피스가 할 일
- 접수 건 상세(RIDER_HELP)에 대화 영역(오래된 순, 라이더·상담원 구분, 처음 내용·사진 번호 위에), 답장 입력(500자, 같은 키 재전송, 처리 끝난 건은 막고 안내), 새 메시지 확인.
- 사건함 목록에 새 메시지 표시(서버 값 그대로).
- 목 → 시험 → 목 모드 캡처. 실서버 답장은 사용자 승인 뒤.
