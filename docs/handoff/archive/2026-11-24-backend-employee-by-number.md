# 사번으로 운영자 찾기 요청 (백오피스 교대 인계 "후임")

보낸 앱: backoffice (PC 2)
받는 백엔드 영역: platform (hr-service — 직원 이름표 employee-labels)

- 근거: 사용자 2026-11-24 "에러난 부분, 어색한 부분 같은 곳 있는지 찾아봐" — 화면 점검에서 교대 인계 쓰기의 **"후임 운영자 ID"** 칸이 운영자 시스템 ID(OP-…)를 직접 쳐 넣게 한다. 직원은 자기·동료의 OP-… 를 모른다(화면 어디에도 글자로 보이지 않게 했다 — ADR-0070 덧붙임). 아는 것은 이름·사번(P2026-00012).
- 지금 받는 것: hr `GET /hr/employee-labels?operatorIds=` — 운영자 ID → 이름·사번(직원 토큰이면 누구나). **반대 방향(사번 → 운영자 ID)이 없다.** `GET /hr/employees`(검색)는 인사팀(HR_ADMIN) 전용이라 상담원·라이더 운영은 못 부른다.
- 클라이언트가 직접 만들지 않는 이유: 사번→ID 표를 화면에 둘 수 없고, 인사 원장 검색을 넓게 여는 것은 개인정보(메일·소속·연락처) 문제라 이름·사번만 주는 좁은 조회가 필요하다.

## 요청
- hr `GET /hr/employee-labels` 에 `employeeNos=P2026-00012,P2026-00014`(쉼표, 최대 50) 거르기를 더해 주세요. 응답 모양은 지금과 같게 `{items:[{operatorId, name, employeeNo}]}`, 모르는 사번은 빠짐(오류 아님), 직원 토큰이면 누구나, 퇴사자 포함 여부는 지금 규칙 그대로(인계 화면은 재직자만 쓰면 좋으니 `activeOnly=true` 같은 선택값이 있으면 더 좋다).
- 이름으로 찾기는 요청하지 않는다(동명이인 — 사번이 정확).

## 받은 뒤 화면
- 교대 인계 "후임": 사번을 넣으면 "[이름] · P2026-00012 에게 넘겨요"로 확인하고 운영자 ID 로 보낸다. 없는 사번·실패면 보내지 못한다. 접수 건 "다른 사람에게 배정(관리자)" 칸도 같게.
