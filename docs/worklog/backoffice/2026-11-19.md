# 2026-11-19 backoffice

## 00:10 더 직관적으로 — 주문 화면 번호·컴플레인 번호·기한 지킴 지난 7일 대비 (backoffice/order-numbers, #159 위)
- 근거: 사용자 "UI·UX 더 직관적으로" → 추천 1·3·4 진행, 2(개발 용어 바꾸기)는 바꿀 말 표를 먼저 보이기로.
- 1 주문 화면: 다른 화면은 화면 번호인데 주문만 시스템 ID 였다. 주문 목록 첫 칸·상세 제목(복사 단추도)·대시보드 최근 주문 = 주문번호 8자리, 시스템 ID 는 "시스템 번호" 칸. 찾기 칸에 8자리면 `orderNumber` 로. 배송 확인 안내 문장도 "주문번호·라이더 번호(또는 ID)".
- 3 목록 첫 칸: 승인·문의 목록은 이미 내용(요약·제목)이 먼저라 그대로. 라이더 컴플레인 목록·상세만 라이더·배송·주문이 시스템 ID 였다(#151 에서 빠짐) → 라이더 일괄·배송·주문 조회로 화면 번호, 상세 제목의 라이더 ID 도 "가린 이름 · 번호"(읽는 중·못 읽음·번호 없음 나눔), 표 머리 "라이더·배송·주문". 배송 번호 여러 개 조회(`useDeliveryNumbers`) 추가.
- 4 처리 기한 지킴 카드: 같은 서버 지표를 바로 앞 7일로 한 번 더 읽어 "지난 7일보다 N%p ▲▼". 앞 기간을 못 읽거나 판정된 건이 없으면 비교 안 함. 목표치는 서버에 없어 만들지 않음.
- 시험: 주문 번호 2개·지난 7일 대비 2개 새로. 자정 직후(00:02) 대시보드 도넛 시험이 깨짐 — 목 주문이 "지금부터 N시간 전"이라 오늘 주문이 없어서. 그 시험만 서울 정오로 시계 고정(Date 만).
- 확인: typecheck·lint·test(67파일 486개)·build:lan 통과. 화면(목, 관리자): 주문 목록 주문번호·상세 제목 74939005, 대시보드 기한 지킴 "지난 7일과 같아요"(목은 기간마다 같은 값), 컴플레인 목록.
- 화면 확인 중 대시보드 숫자가 모두 "?" — 고치는 도중 핫 리로드가 실패해 깨진 모듈이 남아 있었음(코드 문제 아님). 새로 열어 정상 확인.
