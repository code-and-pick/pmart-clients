## 행사 종류 "수량 행사 1+1·2+1"(promotion 0.5.0 QUANTITY_OFFER, ADR-0090)
- 백엔드 요청 `pmart-backend docs/handoff/clients/backoffice/2026-11-26-request-quantity-offer-promotion-screen.md`(B-1·B-2), 사용자 "pr 올려".
- 계약 다시 생성: 백엔드 작업 폴더가 다른 가지(customer-list-segments)라 `git archive origin/main contracts`(49071d73)를 풀어 `PMART_CONTRACTS_DIR` 로. 바뀐 것 — `Promotion.discount` 가 null 될 수 있음, `offer{buyQuantity, freeQuantity}`, `PromotionKind` 에 QUANTITY_OFFER, `/promotions/quantity-offer-items`(고객 앱 몫, 화면에 안 씀).
- 만들기·고치기: 종류에 "수량 행사 1+1·2+1" — 할인 방식·할인값 대신 "사는 수량(개)" 1~10·"더 주는 수량(개)" 1~사는 수량 두 칸과 "N+M (N개 사면 M개 더)" 미리 글, 대상 고르기(SKU·카테고리·테마)는 기간 할인 것 그대로. 보내는 값은 `offer` 만(discount·coupon 없음). 검사 칸 이름 offer·offer.buyQuantity·offer.freeQuantity.
- 목록·상세: 종류 "수량 행사 1+1·2+1", 할인 칸에 "1+1 (1개 사면 1개 더)", 상세에 대상 목록. discount 가 null 이면 "없음"(전에는 늘 있다고 보고 읽어 1+1 이 섞이면 화면이 깨질 수 있었음).
- 승인 상세 행사 줄: 서버가 수량 행사에도 discountType·discountValue 를 AMOUNT·0 으로 실어 "0원"이 나올 뻔 — 수량 행사는 할인 글을 쓰지 않음(N+M 은 서버 요약 "수량 행사 <이름> — N+M").
- 기간 할인 만들기에 "같은 상품에 1+1·2+1 행사가 같이 걸리면 고객은 1+1 만 받아요(기간 할인은 빠짐)"(ADR-0090 A5). 조기 종료 칸의 "받은 쿠폰은 기간까지 쓸 수 있어요"는 쿠폰 행사에만.
- 목: 진행 중 "우유 1+1"(PRM-seed-3), 검사는 서버 `PromotionRules.checkOffer` 와 같은 뜻.
- 확인: typecheck·lint 0, backoffice 전체 145파일 851개 통과(한 번 `alertsAutoRefresh` 시간 시험이 부하로 실패 — 따로 돌리면 통과, 앞 전체 실행도 통과), 시험 3개 더함. 목 화면(1412폭)에서 목록·상세·만들기 눈으로 확인.

## 승인함 일괄 심사
- 사용자 "승인함에 일괄심사 만들어봐 하나하나 보고 승인하기 귀찮으니까". 계약(approval-service)에 여러 건을 한 번에 결정하는 API 는 없어, 고른 건마다 기존 결정 명령 `POST /approvals/{id}/decisions` 를 차례로 보낸다(BatchDecide.tsx).
- 목록: 내가 결정할 수 있는 줄(서버 viewerCanDecide)에만 고르기 칸, 머리에 "모두 고르기". 고르면 띠 "N건 골랐어요 · 고른 것 승인 · 고른 것 반려 · 고르기 풀기" → 확인(고른 건 이름 목록·의견 한 칸, 확인 전에는 안 보냄) → 결과(건별).
- 건마다 상세를 다시 읽어(최신 version·viewerCanDecide) 심사 중이고 내가 결정할 수 있을 때만 보냄(X-Expected-Version). 이미 끝난 건·이제 못 하는 건은 "건너뜀". 거절(Problem·명령 거절)만 "못 했어요"와 사유, 시간 초과·결과 불명은 상세 짝 조회로 해소. ACCEPTED 는 한 번 더 읽어 나의 결정이 있으면 "승인함/반려함", 아니면 "접수됨".
- 키 = 묶음 키 + 승인 ID — "안 된 N건 다시"는 같은 키(이미 들어간 결정은 두 번 되지 않음). 승인·반려만(부분 승인·자료 요청은 상세).
- 다 처리해 목록이 비어도 결과 칸·이름이 남게(표 밖에 둠, 보내기 시작할 때 이름을 붙잡음).
- 확인: typecheck·lint 0, backoffice 전체 146파일 854개 통과(시험 3개 더함), 목 화면 1412폭에서 띠·확인·결과.
