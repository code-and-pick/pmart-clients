# 2026-11-19 rider-backoffice (PC 5)

## 지급 관리·소명·이의 (백엔드 #210·#211 병합·LAN 배포 — 사용자 "병합 했어")
- 생성: `npm run gen:api -w web/rider-backoffice`(백엔드 main 6bf69d04 — execution 0.29.0·rider 0.15.0), contracts.lock 되돌림.
- 지급 관리(`/payouts`, 수행료 묶음): 지급 예정일(비우면 서버 오늘)·상태·라이더로 거르기, 표(라이더 RiderName·예정일·건수·합계·상태·마지막 표시). 결과 표시는 관리자만(PAYING·PAID·FAILED, FAILED 는 사유 필수, 회계 처리 번호 선택). 422 PAYOUT_NOT_DUE·409 는 서버 문구로.
- 소명·이의(`/appeals`, 지원센터 묶음): 상태(기본 결정 대기)·종류·라이더 거르기, 카드(종류·라이더·대상 배송/신청 당시 제한·라이더가 쓴 내용). 유지·인정 + 결정 메모(라이더에게 보임). 수행료 이의 인정 → 응답 adjustmentRequired 면 "이 배송 수행료 조정하기"(`/adjustments?deliveryId=`) — 조정 화면은 그 배송만 보이고, 조정 대기 목록에 없으면 숨기지 않고 이유를 알림.
- 결정·표시가 끝나면 그 줄이 목록에서 빠지거나(결정 대기) 입력 칸이 없어져(지급 완료) 줄 안 알림이 사라졌다 — 시험에서 발견, 결과 알림을 화면 위에 남기도록 고침.
- 조치 이력 코드 4개(PAYOUT_PAYING·PAYOUT_PAID·PAYOUT_FAILED·APPEAL_DECIDED), 오류 문구 PAYOUT_NOT_DUE·APPEAL_EXISTS.
- 열린 점: 수행료 조정(`/rider-earnings/{id}/adjustments`)은 산정 불가만 한 번 — 이미 산정·조정된 수행료나 추가 배달료 반려 건 이의를 인정해도 금액을 바꿀 API 가 없음(백엔드에 물음).
- 검증: typecheck·lint 깨끗, `npm run test -w web/rider-backoffice` 99 통과(새 payoutsAppeals.test 7건). 실서버 확인은 아직.

## 이의 인정 보상금 (백엔드 #214 병합 — execution 0.30.0·rider 0.16.0, 사용자 "보상금 한 줄 따로")
- 생성 다시(백엔드 main 1f9a4ad4), contracts.lock 되돌림. #170·#172 는 PC 1 이 main 에 직접 넣음(89622e4·8743fda).
- 소명·이의: 수행료 이의를 인정하면(adjustmentRequired) 위 알림에 "이의 인정 보상금" 상자 — 금액(1~100,000)·사유 → `POST /rider-compensations`(Idempotency-Key). 결정된 인정 건 카드에도 같은 상자: `GET /rider-compensations?appealId=` 로 이미 준 보상금(금액·지급 상태·예정일·직원)을 보이고, 없으면 주기. 이미 줬는지 못 읽으면 주기를 막고 다시 시도(두 번 주지 않게). 산정 불가 수행료는 조정 화면 링크도 남김.
- 오류 문구 APPEAL_NOT_ACCEPTED·COMPENSATION_EXISTS, 조정 화면 "목록에 없어요" 안내를 보상금으로 바꿈, 지급 묶음 건수 옆 "(보상 n)", 조치 이력 COMPENSATION_RECORDED.
