## 홈 평가 반영 — 출하 약속 기준·작업 상세 조치·"이상 N" (브랜치 mfc/ops-promise-actions)
- 사용자가 붙여 준 외부 평가(홈 → 지연 작업 상세 흐름) 세 가지를 코드로 확인해 모두 맞음 → 사용자 "다 고쳐".
- **출하 약속 기준**: 홈 예외 줄·숫자·탭 제목·대시보드 우선 칩/알림이 작업 `promisedReadyAt`(실제로는 PICK 시작 가능 시각 — 즉시 주문은 접수 시각)으로
  판정하고 있었다. 계약 0.35.0(사용자 결정 2026-11-24)의 출하 약속 = 배차 요청 `estimatedReadyAt` 으로 바꿈.
  숫자 = `GET /shipments/promise-summary`(서버가 셈), 예외 줄 = `GET /shipments?state=PREPARING` 중 배차 요청된 출고의 `GET /shipments/{id}` dispatchRequest(최대 100건, 넘으면 "일부만" 안내) + 끝나지 않은 작업(지금 단계·담당).
  목록(CenterShipment)에 estimatedReadyAt 이 없어 상세를 하나씩 읽는다 — 출고가 많으면 목록에 넣어 달라고 백엔드에 부탁할 만함(PC1 판단).
- **작업 상세 조치 칸**(`#task-actions`): 대기 = 담당 정하기, 배정·진행 = 담당 바꾸기 + 내놓기, 막힘 = 이유(결품 → 결품 처리, 관리자 중지 → 관리자 해제, 부분 종료 중), 끝남 = 조치 없음.
  홈 링크는 조치 칸으로, 막힌 작업 줄은 "작업 상세 — 막힌 이유 보기".
- 상세 필드 "준비 약속" → "작업 목표 시각"(다른 값), 출하·포장에 "출하 약속"(배차 요청 시각, 없으면 "배차 요청 전 — 아직 약속 없음").
- "이상 3" → "확인할 일 3가지"(종류 수).
- 목업: SHP-2·SHP-3 출고를 넣어 "찾을 수 없어요" 없앰, SHP-1·SHP-3 배차 요청(약속 초과), 시연 포장 작업은 배차 요청(지금+25분~). fulfillment `GET /shipments`·`/shipments/promise-summary` 목 추가.
