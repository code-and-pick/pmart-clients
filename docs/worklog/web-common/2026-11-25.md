## 백오피스 화면 기준 2단계 — 목록 찾기 줄(속성 필터·목록 머리)
- 통합 백오피스 목록 16개는 AWS 속성 필터(`PropertyFilter` — 검색칸 → 속성 → 값 → 칩)·목록 머리(`ListHeader`)를 쓴다. 같은 이름·같은 속성으로 `@pmart/web-ui/standard` 에 덮어 목록 화면 모두 한 번에 라이더 틀로:
  - 한 줄 [저장한 보기][찾을 항목 ▾(글자 값 속성이 여럿일 때)][찾기 칸][찾기] | [필터 → 팝업: 속성마다 값 목록 ✓][칩 "속성 값 ✕"][모두 지우기] … [기간·쪽 넘기기]. 값을 고르면 바로 걸리고, 건 값을 한 번 더 누르면 풀린다. 팝업은 늘 그려 두고 닫히면 숨김. 속성마다 값 하나(예전과 같음), 값·속성은 하나도 빼지 않음.
  - 목록 머리 "정보" 글자 → ⓘ(도움말 패널 그대로), 개수·읽은 시각·새로 고침·주 동작 그대로.
- "/" 단축키: 속성 필터 찾기 칸(없으면 필터 단추)으로.
- 시험: 도우미 `test/filter.ts` 를 새 모양으로(필터 팝업의 radiogroup 에서 값, 글자 값은 찾을 항목 + 찾기 칸 + Enter) — 이 도우미를 쓰는 시험은 그대로 통과. 콤보박스를 직접 누르던 8개(단축키·탭 건수·칩·승인함 3·클레임 상태·고객 찾기)를 새 모양으로 고침(확인하는 값은 그대로).
- 확인: typecheck 0(backoffice·hr·ui), lint 0, 시험 backoffice 145파일 839개(전체 실행 때 목 로그인 "새로고침 뒤 세션" 1개 부하로 실패 — 단독 12개 통과, 알려진 것), hr 91개, ui 18개 통과. 목 화면 1400px 클레임·주문 조회 밝음/어두움 캡처 — 라이더 상담 관리와 같은 찾기 줄·필터·칩·표 모양.
- 남은 것: 분할 상세가 아닌 목록의 줄 아래 펼침("전체 상세 ›") — 화면마다 펼칠 내용을 정해야 해 다음 단계. MFC(PC 3)·라이더(PC 5) 앱은 각 PC.

## 백오피스 화면 기준 3단계 — 줄 아래 펼침(사용자 "캡처는 됐고 진행해")
- 대상 고르기: 미리보기 서랍(분할 상세 — 요청서대로 그대로)이 있는 목록 8개(승인함·접수 건·클레임·배송·문의·주문·상품·라이더 컴플레인)는 손대지 않음. 서랍 없이 상세로 가는 목록 중:
  - 행사 목록 — 줄을 누르면 아래로 펼침(▸/▾, 한 번에 한 줄, 다시 누르면 접힘): 대상(앞 3개 + "외 n개")·만든 사람·바뀐 때·승인 링크·제출하면 막히는 곳(서버 problems) + "전체 상세 ›". 줄에 이미 받은 값만(더 읽지 않음).
  - 고객 찾기는 넣지 않음 — 펼치려면 고객 상세를 읽어야 해 개인정보 열람 기록이 남을 수 있다. 콘텐츠 초안은 줄에 다 보이는 것 말고 보일 값이 없어 넣지 않음. 인사 직원 목록은 이미 미리보기 서랍.
- 확인: 시험 1개(펼침·내용·전체 상세 링크·한 줄만·접힘). typecheck·lint 0, backoffice 전체 145파일 840개 통과. 캡처는 사용자 지시로 생략.
