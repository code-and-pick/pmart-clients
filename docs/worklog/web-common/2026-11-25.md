## 백오피스 화면 기준 2단계 — 목록 찾기 줄(속성 필터·목록 머리)
- 통합 백오피스 목록 16개는 AWS 속성 필터(`PropertyFilter` — 검색칸 → 속성 → 값 → 칩)·목록 머리(`ListHeader`)를 쓴다. 같은 이름·같은 속성으로 `@pmart/web-ui/standard` 에 덮어 목록 화면 모두 한 번에 라이더 틀로:
  - 한 줄 [저장한 보기][찾을 항목 ▾(글자 값 속성이 여럿일 때)][찾기 칸][찾기] | [필터 → 팝업: 속성마다 값 목록 ✓][칩 "속성 값 ✕"][모두 지우기] … [기간·쪽 넘기기]. 값을 고르면 바로 걸리고, 건 값을 한 번 더 누르면 풀린다. 팝업은 늘 그려 두고 닫히면 숨김. 속성마다 값 하나(예전과 같음), 값·속성은 하나도 빼지 않음.
  - 목록 머리 "정보" 글자 → ⓘ(도움말 패널 그대로), 개수·읽은 시각·새로 고침·주 동작 그대로.
- "/" 단축키: 속성 필터 찾기 칸(없으면 필터 단추)으로.
- 시험: 도우미 `test/filter.ts` 를 새 모양으로(필터 팝업의 radiogroup 에서 값, 글자 값은 찾을 항목 + 찾기 칸 + Enter) — 이 도우미를 쓰는 시험은 그대로 통과. 콤보박스를 직접 누르던 8개(단축키·탭 건수·칩·승인함 3·클레임 상태·고객 찾기)를 새 모양으로 고침(확인하는 값은 그대로).
- 확인: typecheck 0(backoffice·hr·ui), lint 0, 시험 backoffice 145파일 839개(전체 실행 때 목 로그인 "새로고침 뒤 세션" 1개 부하로 실패 — 단독 12개 통과, 알려진 것), hr 91개, ui 18개 통과. 목 화면 1400px 클레임·주문 조회 밝음/어두움 캡처 — 라이더 상담 관리와 같은 찾기 줄·필터·칩·표 모양.
- 남은 것: 분할 상세가 아닌 목록의 줄 아래 펼침("전체 상세 ›") — 화면마다 펼칠 내용을 정해야 해 다음 단계. MFC(PC 3)·라이더(PC 5) 앱은 각 PC.

## 백오피스 화면 기준 3단계 — 줄 아래 펼침(사용자 "캡처는 됐고 진행해")
- 대상 고르기: 미리보기 서랍(분할 상세 — 요청서대로 그대로)이 있는 목록 8개(승인함·접수 건·클레임·배송·문의·주문·상품·라이더 컴플레인)는 손대지 않음. 서랍 없이 상세로 가는 목록 중:
  - 행사 목록 — 줄을 누르면 아래로 펼침(▸/▾, 한 번에 한 줄, 다시 누르면 접힘): 대상(앞 3개 + "외 n개")·만든 사람·바뀐 때·승인 링크·제출하면 막히는 곳(서버 problems) + "전체 상세 ›". 줄에 이미 받은 값만(더 읽지 않음).
  - 고객 찾기는 넣지 않음 — 펼치려면 고객 상세를 읽어야 해 개인정보 열람 기록이 남을 수 있다. 콘텐츠 초안은 줄에 다 보이는 것 말고 보일 값이 없어 넣지 않음. 인사 직원 목록은 이미 미리보기 서랍.
- 확인: 시험 1개(펼침·내용·전체 상세 링크·한 줄만·접힘). typecheck·lint 0, backoffice 전체 145파일 840개 통과. 캡처는 사용자 지시로 생략.

## 백오피스 화면 기준 4단계 — 상세 머리 ‹ 단추·라이더 사용자 2차 지적(PC 5 전달)
- PC 5 전달 사용자 지적: 상세 제목 위 "‹ 목록" 글자 링크, "적용 안 된 거 너무 많네 — 간격·밑줄·점선 통일 안 됐다". 공용 `@pmart/web-ui/standard`·`standard.css` 에서 한 번에(통합·인사 모든 화면):
  - 상세 머리(DetailHeader)·쪽 머리(PageHeader back): 제목이 맨 위, 제목 왼쪽 둥근 ‹ 단추(이름은 aria-label·title 만). 누르면 앱 안에서 왔으면 브라우저 뒤로(거르기·스크롤 유지), 주소로 바로 열었으면 목록. 한 줄 [‹][제목][표시] … 오른쪽 이전·다음·동작, 요약은 8px 띄워 작고 옅게. 내려가면 위 얇은 띠에 작은 ‹ + 제목. AWS 빵부스러기 줄은 그대로.
  - ⓘ 없앰: 제목 옆 화면 설명·"ⓘ 화면 안내"·목록 머리 ⓘ 모두 그리지 않음(도움말은 머리줄 도움 단추). 1단계의 "ⓘ 로 접기"는 요청서 고침(PC 5)에 맞춰 되돌림.
  - 필터: "모두 지우기" 없앰(칩 ✕·고른 값 다시 누르면 풀림). 찾기 칸에 걸린 글자 값은 칸에 그대로 보이고 칩으로 다시 보이지 않음 — 단 show 로 바꿔 보이는 값(시스템 ID 를 그대로 안 보이게, ADR-0070 "한 고객" 등)은 칸에 넣지 않고 칩으로 남김. 칸을 비우고 찾기 = 그 조건 풀기.
  - 밑줄 하나로: 표·항목값·펼친 줄·구역 안 링크와 .link = 점선, 단추 모양 링크 = 없음, 그 밖 글자 = 없음.
  - 상태 탭(role=tab 전부): 16px 굵게·좌우 20px, 고른 탭 파란 3px 밑줄, 탭 줄 아래 2px 선.
  - 숫자 칸: 이름은 칸 위쪽 같은 줄 굵게, 숫자는 오른쪽 가운데 큰 굵은 글자. 결과 줄: 건수 알약 + 작은 정렬 글자. 항목/값(FieldList): 항목명 작은 회색·값 15px 굵게·칸 최소 11rem·칸 사이 선.
  - 탭 제목 "화면 이름 | 앱 이름"은 이미 그렇게 돼 있음(PageChrome).
- 시험: "‹ 목록" 링크를 누르던 6곳은 ‹ 단추로, ⓘ(list-info) 2곳은 머리줄 도움 단추(help-toggle)로, 찾기 칸 값 2곳은 칩 대신 칸 값으로(확인하는 동작·값 그대로).
- 확인: typecheck·lint 0(backoffice·hr·ui), 시험 backoffice 145파일 842개·hr 91개·ui 18개 통과. 목 화면 접수 건 상세·클레임 조회 한 장씩 부작용 확인(‹ 단추·탭·점선).

## 백오피스 화면 기준 5단계 — 간격·불러오기 실패 상자(PC 5 전달, 사용자 "제목과 내용 시작 간격 답답하지 않게")
- 간격: 쪽 머리 아래 첫 내용까지 16px, 상세 머리(구역 많은 쪽) 아래 24px — 목록 머리가 목록 상자의 머리로 붙는 경우는 띄우지 않음. 찾기 줄은 위에서 28px — 흰 상자 안이면 상자를 띄우고(상자 안 여백 그대로), 상자 없으면 찾기 줄을.
- 공용 `QueryState`(web/ui — 통합·인사·MFC·라이더 모두): 못 읽음·없는 건·권한 없음·확인 중 상자를 라이더 LoadWarning 모양으로 — 둥근 아이콘 · 굵은 제목 · 짧은 한 줄(문의 번호는 그 아래 작게) · 오른쪽 단추(다시 시도 = 주 단추, 다시 확인). 못 읽음 빨강, 일부만 못 읽음 노랑, 확인 중 파랑, 없는 건·권한 없음 회색. 글·역할(alert)·data-state·단추 이름은 그대로.
- 확인: typecheck·lint 0(ui·backoffice·hr·mfc·rider), 시험 backoffice 842·hr 91·mfc 299·rider 256·ui 18 통과. 목 화면 클레임 조회 간격·없는 고객 상자 확인.

## 예전 실패 상자 CSS 지움(PC 5 알림)
- 5단계의 새 QueryState 는 daisyUI `.alert` 를 안 쓰는데, standard.css 의 예전 세로 쌓기 규칙 중 `[role=alert][data-state] > .btn { margin-top }` 이 새 상자 오른쪽 "다시 시도"에 걸려 4px 내려갔다 → 예전 모양용 규칙(:is(.alert)·> h2·> p·> .btn·> p.select-all) 모두 지움. 남은 다른 화면의 한 줄짜리 daisyUI alert(통합 조회 원천 실패·메일함 비밀번호 확인 중)는 daisyUI 기본 모양으로.
