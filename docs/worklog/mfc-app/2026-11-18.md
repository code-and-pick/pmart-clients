## (PC 3) 패킹 시작이 "배정이 바뀌었어요. 작업을 다시 확인해 주세요"로 막히던 것
- 사용자: 피킹 끝 → "패킹 시작"을 누르면 바로 패킹대 스캔으로 가야 하는데 "배정이 바뀌었어요"가 뜬다.
- 원인: 시작 판정(`TaskRules.startRejection`)은 보낸 `assignmentVersion` 을 **capacity 배정** 버전과 비교한다. PDA 는 fulfillment 작업 상세의 배정 버전을 보냈는데, 배정 직후에는 배정 사건이 아직 닿지 않아 상세가 비었거나 옛 버전 → VERSION_CONFLICT. 다음 작업 받기 응답(capacity `Assignment.assignmentVersion`)에는 맞는 버전이 있다.
- 고침: 다음 작업 받기 응답의 배정 버전을 기억(`knownAssignmentVersionsProvider`)해 시작 때 상세 값과 큰 쪽을 보낸다. 그래도 VERSION_CONFLICT 면 상세를 다시 읽어 **내 배정**이고 버전이 달라졌을 때만 새 키로 한 번 더(다른 사람 배정이면 거절 안내 그대로). 목: capacity 배정 버전을 따로 두고(`capacityAssignmentVersions`) 패킹 READY 경우 상세는 옛 버전.
- 확인: 새·고친 테스트 3개(피킹 끝 → 패킹 바로 시작 — 상세 옛 버전, 충돌 → 다시 읽어 시작, 다른 사람 배정이면 다시 안 보냄), analyze 문제 없음, test 200개 통과. 서버 변경 필요 없음.
