# 2026-11-22 rider-app 작업 일지 (PC 5)

## 소셜 로그인 "동의는 처음 가입할 때만" — 앱 몫(RA-1, rider-auth 0.4.0)
- 요청: 라이더 백엔드 세션(PC 5) — 사용자 "라이더쪽을 수정해야해, 소셜로그인부분때문에"(PC 1 백엔드 전달), 고객앱과 같게. 요청서 `../pmart-backend/docs/architecture/service-requests/rider-auth-service.md` RA-1.
- 한 일(`apps/rider_app`):
  - 탈퇴 전 재인증: 네이버로 로그인한 라이더는 `POST /riders/me/withdrawals` 앞에 네이버 인가를 한 번 더 받아 `POST /rider-auth/naver-token-exchanges` 에 `purpose: WITHDRAWAL` (서버가 교환 뒤 네이버 연결을 끊음, 받은 id_token 은 버림). 라이더가 닫으면 신청을 보내지 않고, 실패면 "네이버 확인을 하지 못했어요…"(`wdReauthFailed`). 결과 불명으로 같은 키를 다시 보낼 때는 다시 묻지 않는다. 로그인 교환은 `purpose: LOGIN`.
  - 세션에 로그인 제공자(`provider`)를 저장 — 앱을 다시 켜도 재인증·로그아웃 때 그 제공자를 안다. 2026-11-22 전에 저장한 세션(provider 없음)은 서버 `GET /rider-auth/sessions/current` 의 `provider`(rider-auth 0.4.0, 백엔드 d3bb9459)로 정한다. 그 조회가 실패하거나 null 이면 재인증 없이 탈퇴를 이어 간다(네이버 연결이 남을 수 있음).
  - 구글: 로그인은 지금처럼 버튼마다 `authenticate()`. 탈퇴 끝 → `disconnect()` → `signOut()`.
  - 카카오: 로그아웃·탈퇴 SDK `logout()`(탈퇴 연결 끊기는 서버). 가입을 그만두면(가입 안 마친 세션에서 로그아웃·다른 계정으로) SDK `unlink()` → `logout()`. 구글도 가입을 그만두면 disconnect.
  - **넣지 않은 것**: 카카오 `prompt=login`(매번 로그인 화면)·네이버 `auth_type=reauthenticate`. 요청서에는 있으나 고객앱에서 사용자가 2026-11-21 되돌렸다("로그인 바뀐 게 더 별로" → "예전처럼", ed55e564) — 고객앱 지금 모양과 같게 두었다. 카카오는 카카오톡 있으면 카카오톡.
- 계약: rider-auth 0.4.0 `purpose` — 백엔드 PR #337 브랜치 `delivery/rider-social-consent-once`(d3bb9459, 아직 main 아님)에서 `dart tools/gen_api.dart --only=rider-auth`. 백엔드 main 에 들어가기 전에 합치면 다른 PC 생성물에는 `purpose` 가 없어 빌드가 깨진다.
- 확인: `flutter analyze` 문제 없음, `flutter test` 203개 통과(새 `test/social_consent_test.dart` 14개 — 현재 세션 provider 로 정하기·조회 실패 시 이어 가기 포함 — purpose 본문, 네이버만 재인증, 닫으면 false, 탈퇴 revoke·저장된 제공자로 정리, 가입 그만두기 unlink, 끊기 실패 무시, 세션 provider 읽기). 실기기 시험 안 함.

## 라이더 백오피스 문구 — "처리함"·"끝남" 바꿈
- 사용자 "라이더 백오피스에 지원센터-처리함이랑 끝남 이런 단어 다른 걸로 고쳐".
- 메뉴·쪽 제목 "처리함" → "상담 관리"(배송 사건 상세의 돌아가기 "상담 관리 · 배송 사건"). 탭 "끝남" → "완료", "처리 끝남" → "처리 완료", "끝난 …" 안내 → "완료된 …".
- 같은 낱말을 쓰던 다른 화면도 맞춤: 관제 최근 배송 칸 "끝남" → "완료", 배송 단계 DONE "끝남" → "완료", 도착 예정 FINAL "끝남" → "확정", 라이더 배정 이력 "이 라이더로 끝남" → "이 라이더가 완료", 라이더 문의 칸 "끝난 때" → "완료한 때".
- 주소(`/consults`)·서버 값은 그대로. 공용 web/ui 는 손대지 않음.
- 확인: typecheck·lint 문제 없음, test 191개 통과(시험 문구 맞춤).
- 이어서 사용자 "한 때 를 시점으로 고쳐 완료시점 이렇게": 표 칸 "~한 때" → "~시점" — 완료시점·탈퇴시점·동의시점·기록시점·접수시점(받은 때·보낸 때)·종료시점(닫은·닫힌 때)·답변시점·시작시점(열린 때). test 191개 통과.

## 짧은 화면 번호(ADR-0085) — 라이더 R4785·배송 D74939255
- 요청: 라이더 백엔드 세션(사용자 2026-11-22 결정, 백엔드 PR #350, 알림 `../pmart-backend/docs/handoff/clients/all/2026-11-22-notice-short-display-numbers.md`). 필드 이름은 그대로, 값 모양만 — `riderNumber` `482913` → `R4785`(드물게 5자리), `deliveryNumber` `74939255-1` → `D74939255`(같은 주문 두 번째부터 `D74939255-2`).
- 라이더 앱: 두 필드를 쓰는 곳이 없어 고칠 것 없음(배송 목록은 deliveryId·주문번호).
- 라이더 백오피스:
  - 찾기 칸: 라이더 `^\d{6}$` → `RIDER_NUMBER`(`^[Rr]?\d{4,5}$`, 그대로 보냄). 배송 `parseDeliveryNumber` — D·-순번을 떼고 `orderNumber` 8자리로 찾은 뒤 순번(없으면 1)으로 고름(관제 찾기·배송 찾기). 라이더·탈퇴 목록 입력 칸은 R·숫자 5자리까지만(`riderNumberInput`, "6자리" 문구 → "R4785").
  - 표시: 목록·표·지도 라이더는 번호만(`R4785`), 가린 이름은 title. 상세 머리(관제 라이더 패널·배송 상세 라이더)는 "김*수 · R4785"(`withName`). 번호가 없으면 예전처럼 이름 + ID 끝 "번호 없음".
  - 목: 번호를 새 모양으로, 라이더 번호 찾기는 서버처럼 R 유무를 같게(`sameRiderNo`). 시험 값도 새 모양.
- 확인: typecheck·lint 문제 없음, test 194개(새 `shared/displayNumbers.test.ts` 3개). 브라우저로는 보지 않음.
- 같이 넣음: cases.test 의 "처리 내용" 입력값 '상담 관리' → '배차 다시 요청함'(#383 일괄 치환이 바꾼 것, PC 1 지적).
