## 시연 모드(녹화용)
- 사용자가 라이더앱 기능을 빠짐없이 영상으로 찍고 싶다고 했다("임의로 주문 들어오고 배차되고 … 라이더도 움직이는 것처럼").
- 실주문·실이동 없이 찍도록 시연 빌드를 만들었다: `--dart-define=PMART_ENV=mock --dart-define=PMART_DEMO=true`. 실서버 빌드에는 영향 없음(`kDemo` 가 거짓이면 기존 목과 같다).
- `lib/shared/demo.dart`(새)
  - 시나리오는 기기 파일 `/sdcard/Android/data/com.pmart.rider_app/files/demo.txt` 의 한 단어(`single`·`bundle`·`all`)로 고른다. 다시 빌드하지 않고 편마다 바꾼다.
  - 가짜 위치: 1초마다 지도 목적지(`demoTargetProvider`) 쪽으로 35m 움직이고 10m 앞에서 멈춘다. 목적지는 `RiderMap` 이 그리는 경로의 다음 목적지로 맞춘다.
  - 직선으로 움직인다. 도로 따라가기는 사용자가 원하지 않음("아니 그냥 주문 안 들어온 것만 고쳐").
- 제안 흘려보내기(`MockOfferRepository`)
  - 운행 시작 4초 뒤 첫 제안, 응답할 때마다 6초 뒤 다음 제안을 보낸다.
  - 수락 시간은 보낸 때(`_sentAt`)부터 센다.
  - 만료·거절된 제안은 새 ID(`offerId~n`)로 뒤에 다시 넣어 주문이 바닥나지 않게 한다(2편 녹화에서 주문이 끊김).
- 일반배차 목록(`MockDeliveryListRepository`): 8초마다 한 건씩, 최대 3건까지 보인다.
- 시험 `test/demo_drip_test.dart`(새): 알뜰 시나리오에서 거절·신규배차 끄고 켜기 뒤에도 다음 묶음이 오고, 거절한 묶음은 새 ID 로 다시 온다.
- 1~4편(AI 배차 한집·도움요청·길찾기, 알뜰 묶음, 일반배차, 반품 회수·예약)을 휴대폰 화면 녹화로 찍었다.

## 녹화하다 찾은 것 고침
- **배달리스트의 회수 줄**(실서버에도 해당)
  - 반품 회수 건이 "픽업 바로픽 부산진구 · 주문 …"으로, 반납 뒤에는 "전달지 정보를 불러오지 못했어요"로 보였다.
  - 회수 건은 이렇게 보이게 했다:
    - 받기 전: 회수 핀 · 회수지 주소 · "회수지로 이동해주세요"
    - 받은 뒤: 반납 핀 · MFC · "MFC로 반납하러 가주세요"
    - 아랫줄: 회수 목적(예: 반품 회수)
- **홈 지도 경로**(실서버에도 해당): 회수 중이면 배송 수행 화면처럼 회수지 → MFC 로 그린다(전에는 MFC → 전달지).
- **사진**: 카메라 앱을 여는 동안 Android 가 라이더앱을 내려 목 상태가 날아갔다(3편·4편).
  - 시연 빌드만 카메라 대신 앱이 그린 견본 사진을 쓴다.
  - 실서버 빌드는 그대로 카메라를 쓴다.
