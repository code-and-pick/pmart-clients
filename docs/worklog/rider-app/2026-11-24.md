# 2026-11-24 rider-app 작업 일지 (PC 5)

2026-11-23 의 느낌 고치기(`rider-app/feel-fixes`)에 이어서 같은 가지에서 한 일.

## 조회 실패 표시
- 사용자 휴대폰 캡처를 보고 "불러오지 못했어요 다시 시도 글자랑 UI 너무 없어보여" 라고 했다. 이어서 "다시시도 버튼이 왜 하양색이니?", "ppt로 만든 것 같애" 라고 했다.
- `shared/rider_widgets.dart` 에 `RiderLoadError` 를 새로 만들었다.
  - 작은 회색 와이파이 끊김 아이콘, 제목, 안내 한 줄("연결 상태를 확인하고 다시 시도해 주세요"), 작은 보라 "다시 시도" 버튼으로 이뤄진다.
  - 바탕은 각 화면 색을 그대로 쓴다.
  - 좁은 자리용 `compact` 는 한 줄이다.
- 이 표시를 쓰는 곳:
  - 배달리스트(진행 중·대기)
  - 홈 운행 상태
  - 배송 화면
  - 문의 목록·상세
  - 마이 설정
  - 알림함
  - 배달 내역
- 배달 목록을 못 읽었을 때는 "현재 배달 0건" 줄을 숨긴다. 실패를 0건으로 보이지 않게 하려는 것이다.
- 휴대폰에서 모든 조회가 실패한 일이 있었다. PC 에서는 게이트웨이(health 200)에 닿았으므로, 휴대폰이 같은 LAN Wi-Fi 에 있지 않을 가능성이 크다. 사용자에게 확인을 부탁했다.

## 지원센터 대화
- 사용자: 위 "기타" 칸이 흰 바탕이라 눈에 안 들어오고, 아래 "처리가 끝난 요청이에요"도 잘 안 보인다.
- 요청 칸은 처음 모양 그대로 두고 바탕만 흰색에 가까운 보라(`primaryMist`)로 바꿨다. 사용자가 "폰트나 다른 거 건들지 말고" 라고 했다.
- 처리 끝 안내: 연보라(`primaryPale` #F1EDFF, 새 색) 바탕, 진한 보라(`primaryDeep` = deepViolet) 굵은 글씨, 앞에 체크 아이콘.

## 배달 내역(끝난 배송 보기)
- 사용자: "조금 답답해 보이는 UI야".
- 회색 바탕 위에 둥근 흰 카드 3개(요약·주문정보·도움요청)를 두었다.
- 상태는 색 칩으로 보인다(전달 완료는 보라, 실패는 빨강, 그 밖은 회색). "끝난 배송이에요" 앞에 자물쇠 아이콘을 붙였다.
- 도움요청 줄: 연보라 원 아이콘, 유형, 보낸 시각, 처리 상태 색 칩, 그리고 `>`. 줄 사이에는 얇은 선을 둔다.
- 주문정보 칸 안쪽(`OrderInfoSection`)은 진행 중 배송 화면과 함께 쓰는 부분이라 손대지 않았다.

## 알림함
- 사용자: "계속 반복되는 알림. 몇시에 온 건지도 안 적혀 있고 … 배달이 완료된 후에도 계속 읽으라고 남아있을 이유가 있나? 내역에서 확인하면 되잖아."
- `groupNotifications` 를 더했다.
  - 같은 도움요청(requestId)의 알림은 한 줄로 묶는다. 최신 알림을 보이고 "알림 n개"를 붙인다.
  - 묶은 줄을 누르면 묶인 알림을 모두 읽음으로 바꾼다(하나씩 차례로).
- 줄마다 날짜와 시각을 적는다(오늘·어제는 그 말, 그 전은 "11월 22일 (일) 오후 1:02"). 그래서 날짜 머리글은 뺐다.
- `notificationFeedProvider`: 배송이 끝난 도움요청 알림은 알림함에서 뺀다.
  - 배송을 `GET /deliveries/{id}` 로 확인한다. 끝난 배송은 실행하는 동안 기억해 두고 다시 묻지 않는다.
  - 배송 상태를 못 읽으면 알림을 빼지 않는다.
  - 서버에서 지우는 것이 아니라 화면에서만 뺀다. 서버에는 안 읽음으로 남는다.
- 종 배지는 보이는 줄 가운데 안 읽은 것의 수다.
- 사용자가 "옆으로 밀어서 지우기"를 물었다.
  - 계약에는 알림을 지우거나 숨기는 API 가 없다(목록·한 건·읽음만).
  - 두 가지 안(휴대폰에만 기억, 백엔드 요청)을 설명했다. 사용자: "일단 나중에 할게" — 미룸.

## 앱 아이콘·시작 화면
- 사용자가 새 그림 두 장을 주었다. 아이콘은 보라 둥근 사각에 "P라이더", 시작 화면은 스쿠터 P와 "픽라이더"다. 사용자: "뒷 배경 자르지 말고 그림이랑 글자 크기 그대로".
- 아이콘:
  - 흰 바탕에서 네 모서리와 이어진 밝은 픽셀만 투명으로 바꿔 `tool/icon/pick_rider_icon.png` 로 두었다.
  - `gen_launcher_icon.dart` 로 mipmap 을 다시 만들었다.
- 적응형 전경:
  - 예전처럼 78% 로 줄이면 그림 둘레에 네모 경계가 비쳤다. 그래서 그림을 보이는 영역(72dp)에 그대로 맞췄다.
  - 그 바깥은 그림의 보라를 평면 기울기로 맞춘 색으로 칠했다. 가장자리 6% 는 그 색과 섞는다. 가장자리 색을 줄마다 늘여 칠하던 방식은 줄무늬가 생겨 버렸다.
  - 원·둥근 사각 마스크로 미리보기를 확인했다. 원 마스크에서는 번개 왼쪽 끝이 조금 잘린다.
- 시작 화면: `assets/splash/pick_rider_splash.png` 를 바꿨다. 그림은 그대로 두고 폭에 맞춘다(contain). 바탕 보라는 그림 색 #7D04F2 로 바꿨다(`launch_splash.dart` 와 Android `pick_rider_splash`).

## 공지 읽기
- 사용자 말: "공지 보내는 곳은 있는데 라이더앱에 공지를 읽는 곳은 없네? 보내면 어디로 보내는 거야?"
- 백오피스 공지(notification `sendRiderNotice`)의 흐름: 라이더마다 알림함 한 줄(templateKey `RIDER_NOTICE`, 목적지 NONE)이 생기고, 푸시(FCM 키가 있을 때)도 간다.
- 그런데 앱 알림함에서는 본문이 2줄까지만 보였고, 누르면 아무 데도 가지 않았다. 사용자가 만들자고 했다("응").
- 생성 클라이언트가 계약보다 낡아 `Notification.templateKey` 가 없었다.
  - `dart tools/gen_api.dart --only=notification` 으로 다시 만들었다. `contracts.lock` 은 되돌렸다.
  - 처음 두 번은 셸 작업 폴더가 그 폴더 안이라 지우기가 막혔다.
- `RiderNotification.notice`(templateKey == RIDER_NOTICE):
  - 알림함 줄에 주황 확성기 아이콘과 "공지" 꼬리표를 붙였다.
  - 누르면 읽음 처리를 한 뒤 `/notifications/notice` 로 간다.
  - 이 화면(`NoticeScreen`)은 제목·받은 시각·본문 전문을 보인다. 본문은 글자를 골라 복사할 수 있다.
  - 지우기 API 가 없어 지우기 버튼은 두지 않았다.
- 목: 공지 한 건(`ntf-0`)을 넣었다.
- 시험: `notification_inbox_test.dart` 에 공지 꼬리표 → 전문 → 읽음 시험을 더했다. 전체 231 통과, `flutter analyze` 문제 없음, 남은 `flutter_tester` 없음.
- 휴대폰 푸시로 공지를 눌렀을 때 바로 전문을 여는 것은 아직 하지 않았다. 지금은 푸시 처리(`push_messages.dart`)가 알림함만 새로 읽는다.

## 알림함·공지 다시 그림 — 글꼴·편집

  - Noto Sans KR Black -0.04 / -0.05em·장평 95%
