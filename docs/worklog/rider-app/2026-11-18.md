# 2026-11-18 rider-app (PC 5)

## 위치 권한 — "항상 허용" 요구를 없애고 라이더가 고르게 (사용자 결정)
- 사용자: "라이더에게 위치 권한을 요청한다 · Android 설정에서 '사용 중에만 허용'과 '항상 허용' 중 직접 선택 · 배달 시작 시 위치 추적 포그라운드 서비스 · 배달 중에는 다른 앱으로 전환해도 위치를 서버로 전송". 상시 알림 시작 시점은 물어서 "운행 시작부터(지금처럼)" 유지 — 대기 중에 앱을 내려도 배차 후보에서 빠지지 않게.
- 근거: 위치 포그라운드 서비스를 앱이 화면에 있을 때 켜면 "앱 사용 중에만 허용"이어도 앱을 내린 뒤에도 위치를 받는다. 그래서 "항상 허용"을 요구할 까닭이 없다.
- 바꾼 것:
  - `shared/location.dart`: `BackgroundLocationPermission` → `RiderLocationPermission`(`locationPermissionProvider`). `request()` 는 알림 권한 → 위치 시스템 창(사용 중에만/이번만/거부). 시스템 창이 더는 안 뜨는 "다시 묻지 않음"일 때만 앱 설정을 연다. "항상 허용"으로 올려 달라고 하지 않는다.
  - 홈 안내창은 위치 권한이 **없을 때만** 이번 실행에 한 번(전에는 "항상 허용"이 아니면 매번). 문구: "'앱 사용 중에만 허용'이나 '항상 허용' 중 골라 주세요"(ARB `locationAsk*`).
  - Manifest `ACCESS_BACKGROUND_LOCATION` 은 그대로 둔다 — 설정 창에 "항상 허용" 고르기가 보이게.
- 남은 제약: 앱이 뒤에 있을 때 위치 받기를 새로 시작해야 하는 경우(시스템이 앱을 죽였다 살린 뒤 등)는 "사용 중에만"이면 못 받는다 → 라이더가 앱을 열면 이어지고, 그동안은 관제에 "위치 끊김"으로 보인다.
- 검증: `flutter analyze` 이슈 없음, `flutter test` 102 통과(권한 없음 → 안내·요청 / "사용 중에만"이면 안내 안 함).

## 배터리 최적화 예외 요청 (사용자: 끊김 줄이기 방법 ① 선택)
- 확인한 사실: "항상 허용"이어도 시스템이 앱을 종료하면 상시 알림·위치 전송이 함께 멈춘다(전송이 앱 안에서 돈다). 실제로 앱이 꺼지는 흔한 원인은 제조사 절전 → 배터리 최적화 예외를 권한다. 앱과 따로 도는 네이티브 전송 서비스(②)는 시범 운행에서 끊김이 잦을 때 다시 본다.
- Manifest `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`. `MainActivity` 채널 `pmart.rider/battery`: `isExempt`(PowerManager.isIgnoringBatteryOptimizations), `request`(시스템 창 `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, 못 띄우면 배터리 최적화 목록 설정).
- Dart: `BatteryOptimization`·`batteryOptimizationProvider`(`shared/location.dart`). 홈에서 위치 전송이 켜질 때 이번 실행에 한 번 — 위치 권한 안내 뒤, 예외가 아니면 "배터리 사용 제한 풀기" 안내 → [설정하기]면 시스템 창. 이미 예외면 묻지 않는다. 안내창은 `_confirm` 하나로 묶음.
- 주의: 구글 플레이 출시 때 이 권한 사용 사유(실시간 위치 전송이 핵심 기능) 신고가 필요할 수 있다.
- 검증: `flutter analyze` 이슈 없음, `flutter test` 104 통과(예외 아님 → 위치 안내 뒤 묻기 / 이미 예외면 안 묻기), `flutter build apk --debug` 성공(Kotlin 컴파일 확인). 실기기 시스템 창은 아직 확인 안 함.
