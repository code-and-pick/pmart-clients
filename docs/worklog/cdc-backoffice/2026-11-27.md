## MFC 입고 확인 — "적치까지 끝났는데 왜 계속 출발" (PC 5)
- 사용자: "mfc에서 적치까지 완료했는데 왜 dc백오피스에 계속 출발이라고 되어있니 … mfc에 정상도착 및 입고 완료 정보 받아서 연동후에 이 정보도 볼 수 있는 곳이 따로 있어야".
- 원인: TRF 상태(cdc-outbound)는 출발(DEPARTED)이 마지막이다. MFC 수령 반영은 cdc-inventory 운송 중 재고(Transit)에 있고, DC 운영자 조회 `GET /cdcs/{cdcId}/transits`(0.22.0, MF-1 — #545)가 오늘 LAN 배포됨(백엔드 일지 "LAN transits 200").
- 새 메뉴 "MFC 입고 확인"(`mfc-receipts`, 실시간 관제): 출발 최신 순 — DC 출발·TRF·받는 MFC·보낸·MFC 받은·안 맞음·MFC 입고(입고 전 / 입고·n개 안 맞음 / ✓ MFC 입고 완료, 서버 TransitState 그대로)·반영 시각. 줄을 누르면 출발 → 처음/마지막 반영 → 수량 맞춰 끝남 → MFC 입고 종결 시각, 상품·LOT 별 보낸·정상·격리·판정 전·운송 손실·안 맞음. 상태·출발일 거르기는 주소 쿼리로 서버에.
- TRF 목록: "출발" 옆에 MFC 입고 칸(최근 출발 200건에 없으면 trfId 로 한 번 더). TRF 진행 줄에 마지막 칸 "MFC 입고"(운행 기록 없이도 입고가 있으면 마지막 칸).
- MFC 재고 이동: 다섯째 걸음 "MFC 입고"(오늘 입고 n건, 반영/보낸 수량·안 맞음 n건, 메뉴 링크), 최근 출발 줄에 입고 칸, 펼치면 "MFC 입고" 시각과 문장.
